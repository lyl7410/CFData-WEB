# 增强版路线图与任务清单 v1.0

更新：2026-10-26。原则：同源开发、小 PR、可回滚、人工合并；不直接修改 main。

## 目标与边界

Windows 浏览器界面与 Android 本地 WebView 使用同一提交的 Go 后端和嵌入网页。功能在 Windows 验证后，同一提交构建 APK，再经手机验收；跨平台编译成功不保证系统行为相同。
功能同步指双端具备相同能力；数据同步是另一项独立功能。当前两端各自保存配置/结果，不自动共享。测速数据受设备、网络与时间影响，也不能承诺数值一致。

## P2：自定义功能模块（按优先级逐项 PR）

以下是候选方案，尚无用户指定具体业务功能；先做配置方案，再根据反馈调整，避免一次引入全部功能。

- [ ] 配置方案：多个命名配置、新建/复制/导入导出，schemaVersion、字段白名单、大小限制及向后兼容；不导出密码或 GitHub Token。
- [ ] 结果管理：本地历史、标注收藏、批次对比；保留测试模式、设备/时间信息，避免跨模式误比延迟。
- [ ] 平台适配：网页统一调用能力接口；浏览器下载与 Android 文件保存由适配器实现，拒绝不支持的能力并给出可理解提示。
- [ ] 在活跃 Go 模块内为增强功能划分独立源码文件/包，网页逻辑逐步按职责拆分；只保留少量上游集成点，增加协议兼容测试。
- [ ] 每项功能补充：问题、数据结构、开关/默认值、双端测试、迁移与回滚说明；稳定后再考虑向上游贡献通用修复。

验收：每项功能同一提交双端测试通过；关闭功能仍保持基线流程；不修改根目录历史源码。

## P3：可选跨设备数据同步

- [ ] 先提供手动导出/导入配置（脱敏），这是第一种可验证的跨设备迁移。
- [ ] 再确认是否需要真正自动同步、存储位置与账户方式；不默认上传结果或凭据。
- [ ] 若启用自动同步：认证、加密、schema 版本、冲突检测（保留双方副本）、离线队列、删除传播与可恢复备份；明确同步对象与隐私边界。
- [ ] 网络断开、并发编辑、旧客户端、重复导入、损坏数据测试；设备本地凭据与运行状态不参与同步。

## P4：持续跟进上游

- [ ] 按需检查上游更新；每次以明确 upstream SHA 创建 sync 分支，合并上游到增强版形成 PR。
- [ ] 在隔离分支解决冲突，重点检查更新入口、包名/签名、协议、配置、平台桥接与新增模块。
- [ ] 全套门禁和双端回归通过后人工合并；记录上游基准、冲突解决和增强功能保留情况。
- [ ] 后续可实现仅创建同步 PR 的自动任务；不得自动合并，未完成测试不得自动发版。

上游重大重构可能需要人工移植，模块化能降低冲突，不能保证未来任何更新都自动无冲突融合。
